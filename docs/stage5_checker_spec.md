# Stage 5 — Commentary Checker Spec

Nov 5, 2026 · Updated after the checker review. Write and lock the checker in its own session before any build work starts. Copy this doc into the repo as `docs/stage5_checker_spec.md` and commit it together with the checker.

## Prerequisite

Option A has been checked (stage 3 passes, stage 4 is 250/250, pytest is green, and the locked-file diff is approved) and the repo is pushed.

## Design decisions

| # | Decision | Rule |
|---|---|---|
| D1 | API in tests | A **fake client** returns canned JSON fixtures. The checker makes no network calls. A real call happens only in `scripts/demo_commentary.py`, which is not part of the checker. |
| D2 | Model and key | The model comes from the `CLAUDE_MODEL` env var (default `claude-sonnet-5-5`) and is logged on every call. The key comes from `ANTHROPIC_API_KEY`. `.env` goes in `.gitignore`. |
| D3 | Where numbers come from | Claude never types a digit. Template text with the `{metric_id}` references removed must contain **no digits** and **no number words** (zero to ninety-nine, hundred, thousand, million, billion, percent, half, double, triple). Match number words **on word boundaries**: "retention" contains "ten" and must not be rejected. Months are written as words. "Q3" counts as a digit. |
| D4 | Blocked metrics | If Claude references a blocked metric in a paragraph, the draft is **rejected** (reason `blocked_reference`). It is never rendered as None or a blank. Blocked status is derived from the `metrics` argument (value is None/NaN), never hardcoded. |
| D5 | Questions | Open questions are **generated by code** from the review queue and the blocked metrics, not by Claude. Every draft gets them in a fixed "Open questions" section. |
| D6 | Retries | A rejected draft is regenerated up to 3 attempts in total. If all three fail, `status="rejected"` and no rendered text is returned. |
| D7 | Traceability | Every rendered figure carries `metric_id`, the formatted value, and `sources`. `sources` must equal that metric row's own `inputs`. metrics.py already returns these as `(source_file, source_cell)` tuples, so no stage 4 change is needed. |
| D8 | Injection | Commentary input is only metrics plus review items. Review items **are** sent to Claude, and any file text in them is a quoted JSON string field. The final output never contains "50%" or "fifty percent". |

## Interface the checker tests (`pipeline/commentary.py`)

```python
class ClaudeClient(Protocol):
    model: str
    def create(self, system: str, user: str) -> str: ...   # returns raw model text (JSON)

def draft_commentary(metrics, review_items, client: ClaudeClient,
                     log_path: Path, max_attempts: int = 3) -> Draft: ...
```

**Claude's output format** (validated with a schema; malformed JSON counts as a rejected attempt):

```json
{"sections": [{"company": "cobalt" | "portfolio", "paragraphs": ["Cobalt's net retention fell to {cobalt.12m.nrr_12m} ..."]}]}
```

**`Draft` fields:**
- `status`: `"ok"` or `"rejected"`
- `attempts`: int
- `reject_reasons`: list of str, one per failed attempt, drawn from `made_up_number`, `unknown_reference`, `blocked_reference`, `malformed_output`
- `sections`: each paragraph has `template`, `rendered`, and `figures: [{metric_id, display, sources}]`
- `questions`: list of `{company, metric, period, text}`

**Formatting** (the checker asserts these exactly): ratios are shown as `f"{v:.1f}%"`; `arr_per_employee` as `f"${v:.0f}K"`; dollar amounts in $K as `f"${v/1000:.1f}M"`. No stage 4 metric uses the dollar format today, so it is untested.

**Log:** one JSONL line per client call in `log_path`, with fields `ts, model, attempt, system, user, output`. `attempt` runs 1..n, and `output` equals exactly what the client returned for that call.

## Question rules (test 11)

These were added in the review and are written in the test's docstring:

1. **One question per review item and one per blocked metric**, kept separate. For example, Cobalt April has both a review item (`beginning_arr`) and a blocked metric (`churn_rate`), so it gets two questions.
2. The question's `metric` field is the review item's raw `metric` (or `suggestion`), or the metric name taken from the metric ID.
3. The question `text` contains the item's `source_cell` verbatim (for example `'Metrics'!B12`).
4. The question `text` does **not** echo the review item's `reason`. Reasons can contain file text such as the injection.

## Checker tests (`tests/test_commentary_checker.py`, locked; 30 tests after parametrization)

The checker runs the real pipeline on `data/raw/` to get metrics and the review queue. It never reads `eval/`.

1. **References resolve.** With F1, every `{…}` in every template resolves to a metric row, and no `{` or `}` is left in the rendered text.
2. **Rendered values are exact.** F1 produces exactly 7 figures. Each figure's `display` equals the formatting rule applied to the metrics-table value.
3. **Traceable.** Each figure's `sources` equals that metric's own `inputs`, and each `(file, cell)` exists in the stage 3 table.
4. **Guardrail: made-up number.** F2 → rejected with `made_up_number`.
5. **Guardrail: injection.** F3 (both variants) → rejected. Across every test, no output text contains `50%` or `fifty percent`, case-insensitive.
6. **Blocked metrics are never facts.** F4 → rejected with `blocked_reference`.
7. **Unknown reference.** F5 → rejected with `unknown_reference`.
8. **Malformed output.** F6 (both variants) → rejected with `malformed_output`, with no crash.
9. **Retry recovers.** Sequence [F2, F1] → `status=ok`, `attempts=2`, `reject_reasons=["made_up_number"]`.
10. **Retry gives up.** Sequence [F2, F3, F4] → `status=rejected`, `attempts=3`, and no rendered text is returned.
11. **Questions cover everything open.** Follows the question rules above. Today the pipeline gives 8 review items and 21 blocked metrics, including E7, E6, E1, E2 and E5.
12. **Logging.** The number of log lines equals the number of fake-client calls, including retries. Each line has every log field, `model` equals `client.model`, `attempt` runs 1..n, and `output` equals what the client returned.
13. **Injection stays data.** An injected Harborview review item (revenue, 2026-05, `'Metrics'!Z99`) reaches Claude: the phrase appears in a logged `user` input, only inside a JSON string, never in `system`. The item gets its own question.
14. **No network.** Sockets and the Anthropic client constructor are blocked for the whole module.
15. **Blocked status and values come from the input.** A metrics copy with a newly blocked metric gets that reference rejected and a question added. A metrics copy with a changed value renders the new value.
16. **General number scan.** 11 inline templates ("3 customers", "half", "a hundred", "$5M", "twelve", "triple", "thousand", "two million", "ten percent", "Q3", "ARR will double") are each rejected as `made_up_number`.

## Audit mutations (fresh session, after the loop)

Each mutation must make at least one checker test fail. Revert it after each run.

- Number scan disabled → test 4, 5 or 16 fails
- Number scan reduced to `%` and "percent" only → test 16 fails
- A blocked reference rendered as its value or as "None" → test 6 fails
- Blocked IDs hardcoded → test 15 fails
- An unknown reference rendered as blank → test 7 fails
- Logging skipped on retries → test 12 fails
- An open review item dropped from the questions → test 11 fails
- Review items not sent to Claude → test 13 fails
- Sources taken from the wrong row → test 3 fails
- Formatting changed to 0 decimals → test 2 fails

## Locking

`tests/test_commentary_checker.py`, `tests/fixtures/commentary/**`, `docs/stage5_checker_spec.md` and `.claude/settings.json` are in the deny rules in `.claude/settings.json`. Deny rules only load when Claude Code is started with the repo folder as its workspace (in VS Code: File → Open Folder on the repo folder itself). The `git diff --stat <START_HASH> HEAD -- <locked files>` check in the `/goal` prompt is the real safety net: it catches a change however it was made. Record `START_HASH` after the fixed checker and this spec are committed.
